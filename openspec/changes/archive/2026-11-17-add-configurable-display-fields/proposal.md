# Proposal: add-configurable-display-fields

## Why

The e-paper panel currently renders a hard-coded temperature and relative
humidity layout. The sensor layer already exposes dew point, pressure,
sea-level pressure, CO₂, illuminance, VOC index and PM2.5, so an operator with
different sensors cannot use the panel to show the values they actually care
about. Making the second and third value lines configurable lets one firmware
image serve different sensor combinations while keeping the existing display as
the default.

## What Changes

- Add `DisplayConfig.second_field` and `DisplayConfig.third_field`.
  - `second_field` defaults to relative humidity and is always present.
  - `third_field` defaults to `none`; when set, the panel uses a three-line
    layout.
- Support a fixed vocabulary of display fields: `humidity`, `dew_point`,
  `pressure`, `sea_level_pressure`, `co2`, `illuminance`, `voc_index` and
  `pm25`. Temperature remains the fixed primary value.
- Persist both selections to NVS under keys within the project’s 15-character
  limit, validate them at the storage boundary, and fall back to the documented
  defaults for corrupt or unknown stored values.
- Add two value layouts:
  - second only: temperature baseline 81, second line baseline 124;
  - second + third: temperature baseline 73, second line baseline 107, third
    line baseline 135.
  The value block remains `y 30..139`; the footer geometry is unchanged.
- Render the configured fields with their labels, units and placeholders.
  Secondary lines use `FreeSans12pt7b`. Sea-level pressure requires a
  configured elevation; VOC index requires the SGP40 and its temperature /
  humidity compensation inputs. Missing readings render a placeholder instead
  of a stale value.
- Shrink the warning icon from the current 42 px triangle to a 34 px
  temperature-anchored geometry. The warning moves up with the temperature in
  the three-line layout, and its label sits above the second line so a long
  value such as `SLP 1013 hPa` does not collide with it.
- Extend `RefreshPolicy` with independent second/third slot availability and
  per-field hysteresis, rather than reusing the single temperature/humidity
  validity flag.
- Extend `GET`/`POST /api/display` with string tokens for both fields, and add
  two selects to the E-Paper Display section of the settings page.
- Update the display mock renderer and README screenshots for the new layouts.

**Out of scope:** making the primary temperature configurable; arbitrary
`Sensor::MeasurementType` values; user-configurable labels, units or hysteresis;
changes to the footer, header band or warning vocabulary; new sensor drivers.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `display`: displayed content becomes fixed temperature plus configurable
  second/third fields; two- and three-line layouts; placeholders; warning icon
  geometry anchored to temperature; refresh-policy inputs gain per-slot
  availability and hysteresis; partial-refresh wording covers all configured
  value lines.
- `configuration`: `DisplayConfig` gains persisted second/third field
  selections, defaults and validation.
- `http-api`: the display endpoints expose the new field tokens and accept them
  on update.
- `web-interface`: the E-Paper Display settings section gains second- and
  third-value selectors.

## Impact

- **Source**: `src/Config.{h,cpp}`, `src/PrefsKeys.h`,
  `src/routes/DisplayRoutes.cpp`, `src/display/EPaperDisplay.{h,cpp}`,
  `src/display/DisplayManager.cpp`, `src/display/RefreshPolicy.{h,cpp}` and a
  new native-testable display-field metadata/formatting helper under
  `src/display/`.
- **Web UI**: `data/settings.html` gains two selects and their load/save
  handling; `src/generated/settings_gz.h` is regenerated by the existing
  compression hook.
- **Tests**: native tests for config validation, field formatting, and the
  per-slot refresh policy, including pressure-only sensors and VOC-index
  hysteresis.
- **Docs / mocks**: `scripts/render_host/main.cpp`, the README display mock
  examples and the generated images are updated for the new layouts.
- **Backward compatible**: an unconfigured device keeps `humidity` + `none`,
  i.e. the current two-line display. No new sensor or library dependency; the
  extra config state and code are small compared with the existing display
  footprint.
